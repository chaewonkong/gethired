# spec - onboarding
## 목표
- 처음 사용하는 사용자가, 복잡한 cli 설정 없이 쉽게 이 서비스에 적응하고 쓸 수 있다
- 처음 사용하는 사용자도 자신의 니즈에 맞게 앱 세팅을 안내받고 설정할 수 있다.

## 목표가 아닌 것
- 관심회사 해제 시 DB의 공고 삭제 (soft-delete 포함)

## 기능
- 처음 사용자가 서비스에 진입하면 빈화면에 a. drag-and-drop file upload, b. 클릭시 파일 브라우저를 통한 파일 업로드를 할 수 있는 UI가 보여진다. 
  - 여기서 이력서 파일을 업로드 하면 프로젝트 루트에 resume 디렉토리에 그 파일이 저장된다.
  - resume 디렉토리가 없으면 디렉토리를 생성한다.
- 이력서 업로드 후에는 관심회사를 선택하는 화면을 보게 된다. 여기서 선택하면 DB에 저장되며 추후 필터도, 크롤러도 설정/저장된 회사 리스트로 동작한다.
  - 단, 회사 탭에 가면 관심회사로 등록하지 않은 회사도 확인 가능하며, 관심회사로 추가할 수 있다. (별 모양 아이콘 토글)
- 온보딩 이후에도 이력서를 교체할 수 있다.

## 검증 방법
이 테스트는 현재 repo에서 하지 않고, 안전한 sandbox 또는 유사 공간에 repository를 clone한 뒤 수행한다.
- 최초 진입시 화면에 파일 업로드 화면이 뜬다. drag-and-drop 영역이 표시돼 있고, 업로드 아이콘도 있어 그 영역을 클릭하면 파일 브라우저가 뜨고 업로드가 가능하다
- resume 디렉토리가 없다면 resume 디렉토리를 생성한 후 파일을 저장한다
- resume 디렉토리가 비어 있으면 업로드 화면부터 시작한다
- resume가 비어 있고 관심회사는 저장돼 있으면, 업로드 후 회사 선택 없이 공고 화면으로 이동한다
- resume 업로드가 완료되면 성공을 알리는 toast가 뜬다. 이 토스트는 닫지 않아도 2초 뒤 사라진다
- toast가 사라지면 회사 선택 화면으로 이동한다. 크롤러가 존재하는 모든 회사가 리스팅 되어 있고, Multi-select로 선택 후 확인을 누르면 DB에 선택이 저장된다
- 이후 공고 화면의 필터는 선택된 회사들만 보여주며, "스크래핑 하기" 버튼도 선택된 회사들만 스크래핑한다.
- 사용자는 "회사" 탭에서 자신이 선택한 회사들과 선택하지 않은 회사들을 모두 볼 수 있고, 선택을 취소하거나 추가로 선택할 수 있다.
  - 선택된 회사는 노란 별 아이콘이 활성(칠해짐) 상태이며, 토글로 선택을 on/off 할 수 있다.
- md가 아닌 파일 업로드는 거부된다. 같은 이름의 파일을 다시 올리면 덮어쓴다
- 회사 선택 화면에서 0개 선택 후 확인을 누르면 토스트/모달로 거부된다
- resume는 있고 관심회사가 없는 상태로 진입하면 회사 선택 화면부터 시작한다
- 관심회사를 취소하면 해당 회사 공고가 UI에서 사라지지만 DB에서는 삭제되지 않는다
- 온보딩 이후 이력서 교체 UI로 이력서를 교체할 수 있다

## 결정 사항 (2026-10-15)
- 진입 분기
  - resume 디렉토리가 없거나 md 파일이 없으면(빈 디렉토리) 이력서 업로드 화면부터 시작한다
  - resume에 md 파일이 있고 DB에 관심회사 데이터가 없으면 회사 선택 화면부터 시작한다
  - 빠진 단계만 진행한다: resume가 비어 있고 관심회사는 저장돼 있으면, 업로드 후 회사 선택을 건너뛰고 공고 화면으로 이동한다
- 이력서 업로드
  - md 파일만 허용한다
  - 같은 이름 파일은 덮어쓴다
  - resume 디렉토리는 이미 gitignore 대상이며 커밋하지 않는다
  - 이력서 교체 UI 위치는 구현 시 적당한 곳에 둔다 (추후 피드백으로 조정)
- 관심회사 선택
  - 0개 선택은 허용하지 않는다. 토스트/모달로 알린다
- 관심회사 적용 범위
  - 필터 옵션에는 관심회사만 표시한다. 관심회사가 아닌 회사의 공고는 UI에서 보이지 않는다 (필터는 UI 기능)
  - 관심회사를 취소해도 DB의 공고는 삭제(soft-delete 포함)하지 않는다
  - 크롤링 경로는 "스크래핑 하기" 버튼뿐이며, 관심회사만 스크래핑한다
- 검증: 에이전트가 sandbox 검증까지 수행하고, 이후 사람 게이트에서 추가 QA를 진행한다
