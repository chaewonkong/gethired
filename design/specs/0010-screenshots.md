# spec - README 데모 GIF 생성
## 목표
- README에 골든 패스(이력서 업로드 → AI 선택 → 관심회사 선택 → 스크래핑 → 결과)를 녹화한 GIF가 들어가 있고, 한 명령으로 최신 UI로 다시 찍을 수 있다

## 목표가 아닌 것
- CI. 자동 녹화·커밋·stale 검사 모두 범위 밖. 갱신은 사람이 한다
- 실제 스크래핑·LLM 호출. 결과 화면은 가짜 데이터로 만든다
- 정지 스크린샷(PNG). GIF 한 개만
- GIF의 바이트 단위 재현성. 프레임 타이밍은 매번 달라도 된다

## 기능
- `just screenshots`를 실행하면 데모 모드로 앱을 띄워 골든 패스를 자동 조작·녹화하고 `docs/demo.gif`를 갱신한다
  - 장면 순서: 이력서 업로드 → AI 선택(Claude Code 카드 선택, "로그인됨" 배지 표시 후 계속) → 관심회사 선택 → "스크래핑 하기" 클릭 → 회사별 진행 상태 → 공고 탭에 등급·점수·회사가 있는 카드 목록
  - 뷰포트·스케일(1x)·타임존(Asia/Seoul)·locale(ko-KR) 고정
- 데모 모드(`python -m app --demo`): 스크래퍼와 판정을 가짜로 바꾼 백엔드
  - 회사 4개(등록된 실제 회사 키), 공고 8건(strong 2 · good 3 · stretch 3), 마감 7일 이내 1건
  - 프로필 추출·판정은 고정 결과. 네트워크·LLM·실제 CLI 호출 없음
  - 진행 상태가 보이도록 회사당 판정에 0.5~1초 지연
  - 서버 시각(`now_iso`)을 `2026-10-18T09:00:00+09:00`으로 고정. "마지막 스크래핑"·"수집" 날짜가 항상 같은 값
  - 이력서·DB는 임시 경로. 실제 `resume/`, `backend/data/app.db`, 로그인 세션은 건드리지 않는다
- 데모 데이터(이력서 텍스트, 공고, 판정 문구)는 저장소에 커밋되는 고정 텍스트이고 전부 가상이다. 실제 이력서 내용·실제 공고 금지
- README의 "서비스 소개" 섹션에 `docs/demo.gif`를 상대 경로로 넣는다

## 검증 방법
- `just screenshots` 후 `docs/demo.gif`가 생기고, README의 이미지 링크가 존재하는 파일을 가리킨다
- GIF를 재생하면 위 장면 순서가 모두 보인다. 한글이 깨지지 않고, 마지막 화면에 등급·점수·회사가 있는 카드가 보이며, "마지막 스크래핑 2026-10-18 09:00"이 표시된다
- GIF는 30초 이내, 5MB 이하
- 실행 전후 `backend/data/app.db`와 `resume/` 목록이 같다
- 네트워크를 끊은 상태에서도 `just screenshots`가 성공한다 (데모 모드가 외부 호출을 하지 않음)
- `just test-e2e`는 녹화 spec을 실행하지 않는다 (`playwright test --list`로 확인)
- 데모 데이터 파일을 리뷰해 실제 인물·실제 이력서 내용이 없음을 확인한다

## 결정 사항 (2026-10-18)
- 산출물은 골든 패스 GIF 1개. 흐름이 핵심이라 정지 이미지보다 녹화가 맞고, PNG는 두지 않는다
- AI 선택 단계를 생략하지 않는다. 실제 첫 사용자 흐름과 같아야 한다
- 결과 화면은 seed가 아니라 데모 모드로 만든다. "스크래핑 하기"를 실제로 눌러 job이 돌아가는 모습까지 보여준다. `JobManager`가 scrapers·profile_loader·judge_fn을 주입받으므로 앱 코드 변경은 진입점 수준
- 녹화는 Playwright 비디오 → ffmpeg로 GIF 변환. ffmpeg는 사용자 로컬 의존성(설치 확인됨). 기존 e2e 인프라(임시 경로 서버, 가짜 CLI)를 재사용하고 `just test-e2e`와는 분리한다
- 1x 스케일. 저장소 크기 우선
- 데모 모드에서 서버 시각을 고정해 날짜 표기가 실행마다 바뀌지 않게 한다
- 저장 위치 `docs/demo.gif`, main에 커밋. UI가 바뀌는 커밋 전에 사람이 `just screenshots`로 갱신
- chromium은 Claude Code sandbox 안에서 못 뜨므로 사용자가 직접 실행하는 명령이다
- 실행 계획: `design/plans/plan-0010.md`
