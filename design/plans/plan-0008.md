# plan-0008 codex 지원 · 하네스 선택

## Context

3개 레인을 서브에이전트가 worktree에서 병렬로 진행하고, 통합은 메인 세션이 한다.

## 계약 (A·B·C가 공통으로 보는 응답 형태)
```
GET /api/settings/provider        → 200 {"provider": "claude"|"codex", "chosen": bool}
                                     DB만 조회. provider는 미선택이면 LLM_PROVIDER env → "claude"
GET /api/auth/status              → 200 {"provider": "...", "logged_in": bool, "login_command": "claude login"|"codex login"}
                                     현재 provider만 CLI 확인
PUT /api/settings/provider        ← {"provider": "..."}
                                  → 200 auth/status와 같은 body
                                  → 400 {"detail": "unknown provider: x"}
                                  → 409 {"code": "job_running", "message": "..."}
POST /api/scrape (미로그인)       → 401 {"code": "login_required", "provider": "...", "message": "..."}
```
e2e 가짜 CLI (C가 만들고 통합이 실행). `FAKE_AUTH_FILE` JSON `{"claude": true, "codex": false}`
```
claude auth status   → stdout {"loggedIn": <claude>} exit 0
codex login status   → <codex>면 stdout "Logged in using ChatGPT" exit 0, 아니면 stderr "Not logged in" exit 1
```

## codex CLI 실측 (2026-10-17, codex-cli 0.163.0-alpha.10.2)
- 이 머신의 codex는 ChatGPT.app 내장: `/Applications/ChatGPT.app/Contents/Resources/codex-cli/bin/codex`. PATH alias 없음 → `CODEX_BIN`
- `codex login status`: 로그인 시 stdout `Logged in using ChatGPT` exit 0. 미로그인 시 stderr `Not logged in` exit 1
- 미로그인 `codex exec`는 끝나지 않는다. `--json`에 `{"type":"error","message":"Reconnecting... 2/5 (unexpected status 401 Unauthorized ...)"}` 5회 → HTTPS fallback → `Reconnecting... waiting for network` 무한 반복
- 성공 시 `--json` stdout (stderr 없음)
  ```
  {"type":"thread.started","thread_id":"..."}
  {"type":"turn.started"}
  {"type":"item.completed","item":{"id":"item_0","type":"agent_message","text":"{\"ok\":true}"}}
  {"type":"turn.completed","usage":{"input_tokens":14009,"cached_input_tokens":0,"cache_write_input_tokens":0,"output_tokens":19,"reasoning_output_tokens":0}}
  ```
  `-o <file>`에 마지막 메시지 JSON이 그대로 쓰인다
- 요청 오류는 `{"type":"turn.failed","error":{...}}` 후 exit 1로 즉시 종료 (schema 400 등)
- 호출당 입력 약 14k 토큰이 기본 오버헤드 (codex 시스템 프롬프트)
- strict schema: `additionalProperties: false` 없으면 400 `invalid_json_schema`. Pydantic `model_json_schema()` 원본은 실패. `title`/`default` 제거 + 전 레벨 `additionalProperties: false` + `required` 전체로 변환한 `Batch`는 `minLength`·`minimum`·`maximum`을 포함한 채 통과
- 플래그 확인: `--output-schema <FILE>`, `--json`, `-o`, `-C`, `--skip-git-repo-check`, `-s read-only`, `-m`, `--ephemeral`, `--ignore-user-config`(`$CODEX_HOME/config.toml` 무시, 인증 유지), `-c key=value`, 프롬프트 stdin(`-`)
- 프롬프트를 인자로 넘기면 stdin이 TTY가 아닐 때 stderr에 `Reading additional input from stdin...`. stdin으로 넘긴다
- Claude Code sandbox 안에서는 `codex exec`가 `failed to initialize in-process app-server client: Operation not permitted`로 실패 (`~/.codex` 쓰기 불가). 라이브 확인은 sandbox 밖에서
- `CODEX_HOME=<빈 디렉토리>`로 사용자 세션을 건드리지 않고 미로그인을 재현할 수 있다

## 레인 A: 백엔드 (`backend/`)
### A1 `feat(backend): settings table, env config`
- `config.py`: env override. `DB_PATH`, `RESUME_DIR`, `CODEX_BIN`(기본 `codex`), `CLAUDE_MODEL`(기본 `claude-opus-5-5`), `CODEX_MODEL`(기본 None), `LLM_PROVIDER`(기본 `claude`), `LLM_TIMEOUT_S`(기본 600)
- `repository.py`: `settings(key TEXT PRIMARY KEY, value TEXT, updated_at TEXT)`. `get_setting(key) -> str | None`, `set_setting(key, value, now)`
- 테스트: settings get/set/overwrite, 없는 키 None

### A2 `refactor(backend): llm provider seam`
- `llm.py`: `ClaudeAuthError` → `LLMAuthError`. `PROVIDERS = ("claude", "codex")`, `LOGIN_COMMAND = {"claude": "claude login", "codex": "codex login"}`, 메시지 provider별
- `llm.configure(provider)` / `llm.current_provider()`. `ask_json()` 시그니처 유지, 내부 분기. 미설정 기본 `claude`. codex 분기는 이 커밋에서 `NotImplementedError`
- `MODEL` 상수 → `config.CLAUDE_MODEL`
- `LLM_TIMEOUT_S`를 claude 경로에 `wait_for`로. `query()` 제너레이터 안 raise 금지 규칙 유지
- `jobs.py`, `scripts/match.py`, 기존 테스트의 `ClaudeAuthError` 참조 교체
- 테스트: `configure()` 분기, 기본값, 잘못된 provider ValueError. `conftest.py` autouse fixture로 매 테스트 후 `configure("claude")`

### A3 `feat(backend): codex provider`
- `llm.py` codex 분기
  - strict 변환 `to_strict_schema()`: `title`/`default` 제거, 모든 object에 `additionalProperties: false`, `required`를 `properties` 전체로. `$defs` 포함 전 레벨. 제약 키워드 유지
  - 호출 전 `auth.is_logged_in("codex")` 선체크. False면 exec 안 띄우고 `LLMAuthError`
  - 명령: `$CODEX_BIN exec --json --ephemeral --ignore-user-config --skip-git-repo-check -s read-only -C <빈 임시 디렉토리> --output-schema <임시파일> -o <임시파일> [-m $CODEX_MODEL] -`
  - 프롬프트 stdin. system_prompt는 user prompt 앞에 합친다
  - 결과는 `-o` 파일 JSON 파싱. `--json` stdout은 usage(`turn.completed.usage`)와 오류 감지용
    - `error` 이벤트에 `401 Unauthorized` → 즉시 kill → `LLMAuthError`
    - `turn.failed` → `LLMError(message)`
    - 비정상 종료인데 둘 다 아니면 `is_logged_in("codex")` 재확인으로 auth/기타 분류
    - 타임아웃·취소 시 kill
  - `LLMResult`: `cost_usd=0`, `input_tokens = input_tokens + cached_input_tokens`, `output_tokens`
  - subprocess는 runner 콜러블 주입 (`run_codex(args, stdin) -> (returncode, stdout, stderr)` 형태, 기본은 asyncio subprocess)
- `auth.py`: `is_logged_in(provider)`. codex는 `$CODEX_BIN login status` exit code만. 같은 provider 체크가 진행 중이면 결과 공유(single-flight)
- `main.py`: `OPENAI_API_KEY` pop 추가
- `fixtures/codex_ok.jsonl`, `codex_unauth.jsonl`, `codex_turn_failed.jsonl` (위 실측 출력)
- 테스트 `test_llm_codex.py`, `test_auth.py`
  - 명령 인자(`-C`, `--output-schema`, `-o`, `--ignore-user-config`, `-m` 유무), 프롬프트가 stdin으로
  - strict 변환(`Batch`, `Profile` 실제 schema): `title` 없음, 전 레벨 `additionalProperties`, `required` 전체, `$defs` 안까지
  - fixture별: ok → data·usage / unauth → kill 호출 + `LLMAuthError` / turn_failed → `LLMError`
  - 선체크 False면 exec 미실행, fallback 재확인, 타임아웃 kill
  - `is_logged_in`: codex exit 0/1, 바이너리 없음 → False, 동시 호출에 서브프로세스 1회

### A4 `feat(backend): provider api`
