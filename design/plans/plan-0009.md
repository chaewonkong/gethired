# plan-0009 PDF 이력서 지원

## Context
spec: `design/specs/0009-support-pdf-resume.md`. 이력서로 `.pdf`를 받아 텍스트를 추출해 프로필에 쓴다. 크기 제한은 없애고 LLM 입력 텍스트에 상한을 둔다.

2개 레인을 서브에이전트가 worktree에서 병렬로 진행하고, 통합은 메인 세션이 한다.
- A 백엔드: `backend/`만. 커밋마다 `just test-api`
- B 프론트: `frontend/src/`만. 커밋마다 `just test-web`
- 통합: 머지, `justfile`·`AGENTS.md`, e2e, 라이브 정합성

규칙: 커밋마다 해당 레인 테스트 통과. push 하지 않음. 레인은 자기 경로 밖 파일을 건드리지 않는다.

진행 (2026-10-17): A·B 완료, I1·I2 완료 (pytest 95, vitest 143, e2e 5/5). I3 라이브 정합성은 사용자가 직접 실행

## 계약
```
PUT /api/resume/{name}    body = 파일 바이트 그대로 (Content-Type 무관). 크기 제한 없음
                          → 200 {}
                          → 400 {"detail": "..."}  잘못된 이름 · .md/.pdf 외 확장자 · 텍스트를 추출할 수 없는 PDF
GET /api/resume           → [{name, size, updated_at}]  (.md + .pdf 모두, 형태 변경 없음)
DELETE /api/resume/{name} → 변경 없음 (.pdf도 삭제 가능)
```
- 허용 확장자 `.md`, `.pdf` (소문자, basename만, `.`으로 시작 금지)
- 400 detail 문구: 확장자 `md 또는 pdf 파일만 업로드할 수 있습니다: <name>`, 빈 PDF `텍스트를 추출할 수 없는 PDF입니다 (스캔·이미지 PDF): <name>`
- 프론트 에러 문구(검증 실패 toast)도 위 두 문구를 그대로 쓴다

## 레인 A: 백엔드 (`backend/`)
### A1 `feat(backend): pdf text extraction`
- `pyproject.toml`에 `pypdf` 추가 (`uv add pypdf`)
- `resume.py`: `TEXT_LIMIT = 50_000`, `extract_text(path) -> str`. md는 `read_text()`, pdf는 pypdf로 페이지별 `extract_text()`를 `\n`으로 이어 붙임. 공백만 남으면 빈 문자열. `TEXT_LIMIT` 초과면 잘라서 `\n[이하 생략]` 추가
- 픽스처: `fixtures/resume_sample.pdf`(ASCII 텍스트가 있는 1~2페이지 합성 PDF), `fixtures/resume_blank.pdf`(텍스트 없는 페이지). 실제 이력서 내용 금지. 손으로 쓴 최소 PDF 또는 pypdf `PdfWriter`로 생성한 파일을 커밋
- 테스트 `test_resume.py`: pdf 텍스트 추출, 빈 pdf → "", md 통과, 50k 절단·마커, 깨진 pdf → `ValueError`

### A2 `feat(backend): streaming resume upload, pdf accepted`
- `resume.py`: `_path`가 `.md`/`.pdf` 허용. `MAX_BYTES` 제거. `save(resume_dir, name, chunks: AsyncIterator[bytes])`: 같은 디렉토리의 임시 파일(`.<name>.tmp` 등 dotfile)에 스트리밍 후 `os.replace`. 실패 시 임시 파일 삭제. 저장 후 pdf면 `extract_text`를 `run_in_threadpool`로 돌려 빈 문자열이면 파일 삭제 + `ValueError`
- `list_files`: `*.md` + `*.pdf`, 이름순. 임시 dotfile 제외
- `api.py`: `PUT /api/resume/{name}`이 `Request.stream()`을 그대로 `save`에 넘김. `ResumeBody` 제거. `ValueError` → 400 detail
- 테스트 `test_api.py`: pdf 업로드·목록·삭제, md 업로드(raw body), 빈 pdf 400 + 파일 미생성, 확장자 400, 큰 바디(예: 5MB 더미 md) 성공, 덮어쓰기, 임시 파일이 목록에 안 보임

### A3 `feat(backend): profile from md and pdf`
- `profile.py`: `source_files()`가 두 확장자. `extract()`가 `resume.extract_text`로 문서 본문 구성. `source_hash`는 청크(1MB) 읽기. "no *.md files" 메시지 갱신
- 테스트: 픽스처 pdf + md 혼합 디렉토리에서 `ask_json` fake로 프롬프트에 두 문서가 `<document name=...>`로 들어가는지, 해시가 pdf 바이트 변경에 반응하는지

### A4 `feat(backend): resume-text debug script`
- `scripts/resume_text.py [name...]`: `RESUME_DIR`의 지정 파일(없으면 전부)을 `extract_text`로 뽑아 `out/resume_text/<name>.txt` 저장, 글자 수·절단 여부 출력

## 레인 B: 프론트 (`frontend/src/`)
### B1 `feat(frontend): upload pdf resumes`
- `api.ts`: `putResume(name, file: Blob)`이 `File`을 fetch body로 그대로 전송 (`Content-Type: application/octet-stream`). 400은 body `detail`을 메시지로 하는 `Error`
- `ResumeDropzone.tsx`: `accept=".md,.pdf"`, 안내 `Markdown(.md) · PDF(.pdf) · 여러 파일 가능`. `invalidResumeFiles`: 크기 검사 제거, 확장자 메시지 `md 또는 pdf 파일만 업로드할 수 있습니다: <names>`. `MAX_RESUME_BYTES` 제거
- `App.tsx`: `uploadResumes`에서 `f.text()` 대신 `File` 전달. 서버 400(빈 PDF 등)은 에러 toast로 detail 표시, 나머지 파일은 계속
- 테스트: `Onboarding.test.tsx`·`App.test.tsx`의 `stubBackend`가 PUT body를 bytes로 받도록, pdf 업로드 성공, 확장자 거부 문구, 1MB 초과 파일이 이제 통과, 서버 400 detail toast

## 통합 (메인 세션)
### I1 머지
- main에 A → B 순서로 rebase 머지. `just test`
- e2e(sandbox 밖): 기존 `uploadResume` 헬퍼가 raw body로 동작하는지 5/5 확인

### I2 `chore: pdf resume docs`
- `justfile`: `resume-text *args`
- `AGENTS.md`(루트·backend·frontend): resume.py 설명(md·pdf, 스트리밍, 50k 상한), 1MB 문구 제거, 드롭존 설명, 디버그 명령

### I3 라이브 정합성 (사용자 동석)
- 에이전트의 sandbox 밖 실행이 거부되어 사용자가 직접 수행. 이력서 내용은 에이전트 컨텍스트에 넣지 않는다
- `resume/`에 `resume.md`만 두고 `just match <회사> --limit 5` → `profile_cache`의 프로필 A. `resume.pdf`만 두고 같은 명령 → 프로필 B. `core_skills`·`domains`·`years_experience`·`preferences` 비교
- `just resume-text resume.pdf`로 추출 텍스트 육안 확인 (다단 레이아웃 순서 깨짐 여부). 깨지면 `pdfplumber` 교체 검토
- 업로드 화면에서 md·pdf 모두 지원 문구 확인
