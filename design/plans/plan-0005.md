# plan-0005 온보딩

## Context
spec: `design/specs/0005-onboarding.md`. 처음 사용자가 CLI 없이 웹에서 이력서 업로드 → 관심회사 선택까지 마치고, 이후 필터·스크래핑·모든 탭이 관심회사 기준으로 동작하게 한다.

규칙: 커밋마다 `just test` 통과. push 하지 않음.

진행 (2026-10-15): 1~7 완료 (sandbox E2E 34/34 통과). 사람 QA 대기

## 1. `feat(backend): resume file api`
- `app/resume.py`: `list_files`, `save`, `delete`. 파일명은 `Path(name).name`, `.md`만, 1MB 제한, 디렉토리 자동 생성, 같은 이름 덮어쓰기
- `api.py`: `GET /api/resume`, `PUT /api/resume/{name}` (`{content}`), `DELETE /api/resume/{name}`. `create_app`에 `resume_dir` 인자
- 테스트: 저장·덮어쓰기·공존, 확장자/크기 거부, path traversal 차단, 디렉토리 생성, 삭제·404

## 2. `feat(backend): interest companies`
- `repository.py`: `interests (company PK, created_at)`, `list_interests` / `set_interests` / `set_interest`
- `api.py`: `PUT /api/interests` (0개·unknown 400), `PUT|DELETE /api/companies/{c}/interest`, `/api/companies`에 `interested`
- `POST /api/scrape` 파라미터 없으면 관심회사만, 0개면 400
- 테스트: CRUD, 0개 거부, FakeScraper로 관심회사만 스크래핑, 해제 후 공고 보존

## 3. `feat(frontend): onboarding flow`
- `api.ts` 래퍼, `Company.interested`
- `Toast`(2초 자동 닫힘, `onClose`), `ResumeDropzone`(드래그앤드롭·클릭, 다중, 프론트 검증), `CompanySelect`(초기 전부 해제, 0개 거부)
- `App`: 단계 계산 upload / select / main. 업로드 후 toast가 닫히면 reload → 재계산 (빠진 단계만 진행)
- 테스트: 단계 분기, toast 2초 후 전환, 0개 거부, 확장자 거부

## 4. `feat(frontend): filter postings by interest companies`
- `App`에서 관심회사 공고만 걸러 모든 탭·배지에 전달. `CompanyFilter`에도 관심회사만
- `CompaniesTab` 별 토글. 마지막 해제 시 단계 계산으로 선택 화면
- 테스트: 비관심 공고 제외(탭·배지), 별 토글, 마지막 해제 → 선택 화면

## 5. `feat(frontend): resume manager`
- `ResumeModal`: 헤더 "이력서" 버튼. 파일 목록·삭제·업로드. 업로드 시 toast만, 마지막 삭제 → 업로드 화면
- 테스트: 업로드·삭제·마지막 삭제 전환

## 6. `docs: onboarding`
- backend/frontend `AGENTS.md`, README "이력서 준비", 이 문서 진행 상태
