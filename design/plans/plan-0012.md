        # 다른 프로세스 보유: 락 파일이 없으면 False. 있으면 O_RDONLY로 열어 fcntl.flock(LOCK_SH|LOCK_NB) 실패 여부로 판단.

API 매핑(A1): `POST /scrape` = 자기 프로세스 `current`가 running이면 **prepare 전에** 202 + 그 job_id(기존 동작, 로그인 CLI를 다시 돌리지 않음) → `prepare()` → `LoginRequired` 401(`login_command` 포함) / `NoTargets` 400 → `start()` → `JobRunning`(다른 프로세스) 409 `{code:"job_running", message}`. `PUT /settings/provider`는 `is_locked()`면 409.

CLI JSON 계약(B2가 키 집합을 테스트로 고정, D가 SKILL.md에 적는다):
```
status  --json → {resume_count, provider, chosen, interests:[...], last_success:{company:{finished_at,...}}, stale, job_running}
postings --json → [{id, company, title, fit_level, score, fit_reason, apply_url, deadline, scraped_at}]  (--full: +summary, gaps)
companies --json → /api/companies 와 동일
scrape --json → Job.to_dict() + failed:[{company, error}]   (to_dict에 error 포함)
오류 → {code, message, login_command?, job?}   # job: scrape가 시작된 뒤 실패·중단된 경우 부분 결과(to_dict)
```
exit code 표(B2 테스트가 이 표를 그대로 고정):

| 경우 | exit | code |
|---|---|---|
| 성공 (일부 회사 실패 포함) | 0 | — (`failed` 배열) |
| 모든 회사 실패 | 1 | `all_failed` |
| 프로필 추출 실패 (`Job.error` 로 판별) | 1 | `profile_failed` + `job` |
| 관심회사 0 / unknown company | 1 | `no_targets` |
| 다른 프로세스가 락 보유 | 1 | `job_running` |
| 텍스트 없는 PDF `resume add` | 1 | `invalid_resume` |
| `status`·`postings`에서 DB 없음 | 1 | `not_onboarded` |
| `--since abc` 등 입력 오류 | 1 | `invalid_argument` |
| 미로그인 선체크 | 3 | `login_required` + `login_command` |
| 도중 `auth_required` | 3 | `login_required` + `login_command` + `job`(부분 결과) |
| Ctrl+C 중단 | 130 | `interrupted` + `job`(`job.status == "interrupted"`). 락 해제, 진행 중 run은 `failed`/`interrupted` |
